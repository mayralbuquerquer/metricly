# Requisitos — Metricly

## Regras de Negócio

### RN01 — Informações obrigatórias
Uma demanda somente poderá ser submetida quando os campos obrigatórios estiverem preenchidos.

### RN02 — Possíveis duplicidades
Durante a triagem, possíveis demandas duplicadas ou relacionadas deverão ser verificadas antes da entrada no backlog.

### RN03 — Priorização
A prioridade deverá ser definida durante a triagem utilizando critérios padronizados de impacto e urgência.

### RN04 — Atribuição
A atribuição das demandas deverá considerar a capacidade atual da equipe e a especialidade dos profissionais.

### RN05 — Comunicação
O solicitante e os envolvidos deverão ser informados sobre alterações relevantes no ciclo de vida da demanda.

### RN06 — Prazo
O prazo deverá considerar esforço estimado, capacidade disponível, prioridade e a data desejada pelo solicitante.

---

## Requisitos Funcionais

### RF01 — Cadastro de demanda
O sistema deverá permitir o cadastro de uma nova demanda.

### RF02 — Validação de campos
O sistema deverá validar o preenchimento das informações obrigatórias antes da submissão.

### RF03 — Consulta de demandas
O sistema deverá permitir que o solicitante consulte suas demandas cadastradas.

### RF04 — Triagem
O sistema deverá permitir que a equipe de Tecnologia realize a triagem das demandas.

### RF05 — Priorização
O sistema deverá permitir a definição da prioridade de uma demanda.

### RF06 — Responsável
O sistema deverá permitir atribuir um profissional de Tecnologia como responsável.

### RF07 — Status
O sistema deverá permitir a atualização do status da demanda.

### RF08 — Histórico
O sistema deverá manter histórico das alterações de status.

### RF09 — Sprint
O sistema deverá permitir associar demandas a uma sprint.

### RF10 — Indicadores
A solução deverá disponibilizar dados para acompanhamento de indicadores gerenciais.
