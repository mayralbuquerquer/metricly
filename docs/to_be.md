# Processo TO-BE — Metricly

## Processo Proposto

Com base nos problemas identificados no processo atual, foi definido um fluxo futuro para centralizar e padronizar a gestão das demandas de Tecnologia.

Solicitante identifica uma necessidade  
↓  
Registra a demanda de forma padronizada  
↓  
Sistema valida as informações obrigatórias  
↓  
Demanda é encaminhada para triagem  
↓  
Equipe verifica possíveis demandas relacionadas ou duplicadas  
↓  
Impacto, urgência, prazo desejado e complexidade são analisados  
↓  
Demanda é aprovada ou rejeitada com justificativa  
↓  
Prioridade é definida utilizando critérios padronizados  
↓  
Demanda aprovada entra no backlog  
↓  
Responsável é definido considerando especialidade e capacidade  
↓  
Demanda é analisada e estimada  
↓  
Execução e atualização de status  
↓  
Solicitante acompanha o andamento  
↓  
Demanda é concluída  
↓  
Solicitante valida a entrega  
↓  
Demanda é encerrada e os dados ficam disponíveis para indicadores

## Benefícios Esperados

- maior rastreabilidade das solicitações;
- padronização do processo;
- melhor visibilidade sobre o backlog;
- priorização mais consistente;
- melhor acompanhamento da carga de trabalho;
- maior autonomia para o solicitante acompanhar suas demandas;
- geração de dados para indicadores gerenciais.
